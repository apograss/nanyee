# ADR 0001：账号绑定邮箱与找回密码

- 状态：已接受（2026-10-28）
- 背景事件：两位用户忘记旧账号密码后用学号重新注册，旧账号下的自动评课任务无法取消，只能人工排查。

## 背景

- 全站 115 个用户中 114 个通过社区答题注册（`COMMUNITY_QUIZ`），没有任何人绑定邮箱，忘记密码后无法自助找回。
- `users.email`（全局唯一）、`users.email_verified_at` 字段已存在，`registration/mailer.py` 已支持 Cloudmail 网关与 SMTP 发信，生产环境均已配置。

## 决定

1. **可绑定任意邮箱**，不限 edu 后缀（学生主要用 QQ 邮箱）。
2. **绑定可选，不强制**。在以下位置提示未绑定的用户：开自动评课时、保存学校凭据时、注册成功后（可跳过）、个人页常驻。
3. **一个邮箱只能绑一个账号**，沿用 `users.email` 唯一约束。
4. **绑定 / 换绑 / 解绑**：
   - 新邮箱需通过 6 位验证码验证。
   - 换绑和解绑需要输入当前平台密码。
   - 换绑或解绑成功后，向旧邮箱发送通知。
5. **找回密码只需输入邮箱**：
   - 邮件发送 6 位验证码（不用链接，QQ 邮箱常拦截或折叠链接），15 分钟有效，限制尝试次数；邮件中附带该邮箱对应的用户名，便于忘记用户名的人。
   - 不论邮箱是否已绑定，接口返回同样的提示，不暴露账号是否存在。
   - 复用现有的 Turnstile 与限流（按 IP、按邮箱分桶）。
   - 重置成功后吊销该用户所有会话，要求重新登录；更新 `password_changed_at`。
6. 验证码流程复用现有 challenge 机制与 mailer，新增用途（绑定邮箱、重置密码），不另起一套。

## 后果

- 只能帮助以后的用户；已经忘记密码且未绑邮箱的存量用户仍需人工处理，或通过 [ADR 0002](0002-school-account-conflict-takeover.md) 自助停掉旧任务。
- 邮件投递成为找回流程的依赖，需要监控发信失败。
