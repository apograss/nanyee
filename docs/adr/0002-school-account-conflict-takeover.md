# ADR 0002：同一学号在其他账号上的评课任务——验证后停止

- 状态：已接受（2026-10-28）
- 相关：[ADR 0001](0001-account-email-binding-and-password-reset.md)

## 背景

用户忘记旧平台账号后重新注册，旧账号下的自动评课任务仍在每晚运行，新账号看不到也停不了。学校账号保存在加密凭据中，无法按学号查询，人工排查只能批量解密。

保存学校凭据时**不会**去学校登录验证（`create_credential` 只做格式校验）。因此"输入了某个学号"不能证明学号归属，如果据此展示冲突信息或允许停止任务，会造成：

- 任何人填别人的学号即可停掉别人的任务；
- 任何人填一个学号即可探知"该学号在用本站自动评课"，这正是用户最担心的隐私问题。

## 决定

1. **学号盲索引**：`hosted_credentials` 新增 `account_digest` 列（带索引），值为规范化学号（去首尾空白）的 HMAC-SHA256。HMAC 密钥为独立的新配置项（如 `NANYEE_SCHOOL_ACCOUNT_DIGEST_KEY`），不复用凭据主密钥或 Session Secret。只对学校账号类凭据（`SCHOOL_ACCOUNT_PURPOSES`）计算；创建和更新凭据时写入。
2. **存量补算**：上线时在 worker 容器内运行一次性脚本，解密存量学校凭据，只写入 `account_digest`，不输出明文、不记录日志中的学号。
3. **保存凭据时不展示任何冲突信息。**
4. **用户主动触发"检查并停止该学号的其他评课任务"**：
   - 服务端先用该用户自己的这条学校凭据实时登录学校（验证码 OCR）。
   - 登录失败：返回通用失败，不透露是否存在冲突。
   - 登录成功：按 `account_digest` 查找**其他账号**下的同学号凭据，取消其上的活跃评课任务（`QUEUED` / `RUNNING` / `RETRY_WAIT`），撤销这些凭据；告诉用户停止了几个任务，**不透露旧账号用户名**。
   - 需要 CSRF、Turnstile 与限流（同步学校登录成本高，且可被用来试探密码）。
5. **范围只限自动评课**。学习舱是用户主动发起的短任务，不在此列。
6. **通知旧账号**：被停止的任务记 `error_code = CLAIMED_BY_OTHER_ACCOUNT`，旧账号看到 `evaluation_claimed` 站内通知（30 天）。运行中被停止的任务收尾时保留这个原因。旧账号邮件提醒暂未实现。

## 实现说明（2026-10-28）

- 接口：`POST /api/v1/smu/school-account/stop-other-evaluations`（`credential_id` + 验证码 `flow_id` / `captcha`）。验证码沿用 `/smu/captcha`，由浏览器端 OCR 自动识别，识别错时前端自动换图重试。
- 前端入口：授权管理页“忘了旧账号，停不掉之前的自动评课？”卡片。
- 未配置 `NANYEE_SCHOOL_ACCOUNT_DIGEST_KEY` 时接口返回 503，其余功能不受影响。

## 后果

- 学校登录验证成为这项操作的前提：学校侧不可用或验证码识别持续失败时，用户无法自助停止，仍需人工处理。
- 新增一个必须妥善保管、不能轮换丢失的密钥：轮换 `account_digest` 密钥需要重新补算全部存量凭据。
- 盲索引降低了按学号查询的成本，但没有密钥时无法从摘要反推学号。
